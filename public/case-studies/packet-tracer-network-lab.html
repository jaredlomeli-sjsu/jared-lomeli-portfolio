Case Study

Segmented Enterprise Network Lab

A three-VLAN enterprise network built in Cisco Packet Tracer, exercising Security+ SY0-701 Chapters 3–4 in a single working topology — segmentation, AAA, detection, encrypted remote access, and enterprise wireless, all in one build rather than five separate exercises.

Cisco Packet Tracer Networking VLANs VPN AAA Security+

The Goal

Most Security+ study guides cover segmentation, AAA, IDS, VPNs, and wireless security as separate, disconnected topics. I wanted to see how they actually fit together on one network, so I built a single topology in Cisco Packet Tracer that exercises all of it at once: three VLANs behind a Layer-3 core switch, a full AAA stack, an IDS tap, a site-to-site VPN to a remote branch, and WPA2-Enterprise wireless — the same design decisions a small business network would actually need to make together, not in isolation.

Network Zones

Zone VLAN Subnet What's in it
Management / IT 10 192.168.10.0/24 Jump server, TACACS+ server, RADIUS server, IDS monitor, syslog server, honeypot, IT workstation
Employees 20 192.168.20.0/24 Employee workstations
Servers / Wireless 30 192.168.30.0/24 DHCP/DNS server, wireless access point, wireless laptop
Remote Branch — 10.20.0.0/24 Remote router, remote switch, branch workstations — reached via the site-to-site IPSec VPN

One deliberate simplification from the guided lab this was based on: Servers and Wireless share one VLAN here instead of a separate DMZ subnet — a real tradeoff, not an oversight, made to keep the topology to a size I could fully reason about end to end.

What's Configured

Segmentation

  • 3 VLANs on a Layer-3 core switch (Cisco 3560)
  • Inter-VLAN routing via SVIs
  • ACLs restricting traffic between zones
  • Port security (sticky MAC, violation = shutdown)
  • BPDU Guard on access ports
  • DHCP snooping, single trusted uplink

AAA

  • TACACS+ for device administration
  • RADIUS for WPA2-Enterprise 802.1X
  • Local fallback authentication on network devices

Detection & Monitoring

  • IDS sensor fed by SPAN from the core switch
  • Centralized syslog from the edge router and switches
  • Honeypot decoy in the Management/IT zone
  • SNMP v3 on the edge router (SHA auth, AES-128)

Remote Access & Wireless

  • Site-to-site IPSec VPN (IKEv1, AES-256, SHA-256, DH group 14, pre-shared key)
  • ACL-defined interesting traffic for the VPN
  • SSH-only device administration, Telnet disabled
  • WPA2-Enterprise via RADIUS, 802.1X port-based access
  • NAT/PAT overload on the edge router

What I Learned

The most useful part of building this wasn't any single configuration — it was seeing where concepts that look similar on paper turn out to solve different problems in practice:

VLANs segment, they don't encrypt

Traffic within a VLAN is still fully visible to anyone with SPAN-level access. Segmentation controls where traffic can go, not whether it's readable once it gets there — that's a separate problem VLANs alone don't solve.

TACACS+ and RADIUS aren't interchangeable

TACACS+ is for device administration — it encrypts the full packet and separates authentication, authorization, and accounting into distinct steps. RADIUS is for network access, like 802.1X and VPN logins. Same acronym-adjacent category, genuinely different jobs.

Sticky-MAC port security is a small control with an outsized payoff

The switch learns the first MAC address on a port and shuts the port down the moment a different one shows up. Almost no configuration effort for a control that directly blocks a whole class of rogue-device and MAC-spoofing attempts.

SNMP v1/v2 still show up in the wild

Both send community strings in plaintext, and the defaults (public/private) are still common on real, unhardened devices. SNMP v3 with SHA authentication and AES encryption is the only version I'd consider acceptable in production — it's what's configured here.

WPA2-Personal and WPA2-Enterprise look similar, aren't

Personal shares one pre-shared key across every user on the network. Enterprise gives each user their own credentials via RADIUS and 802.1X — meaning a compromised or departing user can be revoked individually instead of forcing a password change for everyone.
