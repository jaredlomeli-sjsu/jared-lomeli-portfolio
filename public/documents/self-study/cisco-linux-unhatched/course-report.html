About This Course

Linux Unhatched is a free, self-paced introduction to Linux offered through Cisco Networking Academy, built by NDG (Network Development Group). It's an 8-hour, beginner-level course with no prerequisites, taught through instructional material paired with a live Linux virtual machine that runs directly in the browser — no local install required.

The course covers basic command-line navigation, file management, permissions, and system configuration. It's aligned to a portion of the LPI Linux Essentials exam objectives. Cisco/NDG recommend continuing on to NDG Linux Essentials or NDG Linux I after finishing this course — for me, this course is groundwork for CompTIA Security+ (SY0-701), the certification I'm actually studying toward next, not CompTIA A+.

This report is built from my own handwritten notes taken during the course, organized here by topic with added context on why each command matters in practice — both as a general system administrator and from a cybersecurity angle, since that's the direction I'm headed.

Navigation & Paths

ls — List Files

List → shows a listing of information about the files inside a directory.

ls [options] [arguments]

Key flags: -l long listing (permissions, owner, size, date) · -r reverse alphabetical order · -v verbose (extra operation detail). Flags can be combined in any order: -lr = -l -r = -rl.

Example: ls -lr Documents — long, reverse-alphabetical listing of the Documents directory.

Sysadmin angle: -l is the fastest way to eyeball who owns a file and what permissions it has before troubleshooting a "permission denied" error.
Cybersecurity angle: ls -la is a standard first recon step — it reveals hidden dotfiles, unexpected SUID binaries, or recently modified files after a suspected compromise.
pwd — Print Working Directory

Prints the directory you're currently standing in.

pwd [options]

Note: ~ is shorthand for "where we are" (home directory). A prompt like sysadmin@localhost:~$ shows the machine name (localhost) and current location (~).

Sysadmin angle: Confirms your working location before running a destructive command like rm -r — never delete blind.
Cybersecurity angle: During incident response, pwd is the first sanity check after pivoting through a shell (especially a reverse shell) to know exactly where you landed on the filesystem.
cd — Change Directory

Moves you to a different directory.

cd [options] [arguments]

Note: / is the root directory — Linux's equivalent of "My Computer." cd / moves you there.

Sysadmin angle: Fast directory traversal is the backbone of every CLI workflow — muscle memory here saves real time doing routine admin work.
Cybersecurity angle: Attackers with shell access use cd to explore a compromised host's directory tree, looking for config files, credentials, or writable directories to stage payloads.
Absolute Path

The exact, full location of a directory, always starting with /.

Example: home directory = /home/sysadmin = ~

Sysadmin angle: Scripts and cron jobs should always use absolute paths — relative paths break silently when a script runs from an unexpected working directory.
Cybersecurity angle: Malware frequently hardcodes absolute paths like /tmp or /dev/shm because those locations are reliably writable — recognizing them in logs is a red flag.
Relative Path

Starts from a directory name rather than /; can span multiple layers (e.g. /School/Art). Go back one level with cd ...

Sysadmin angle: Handy for quick day-to-day navigation, but risky in automation — the same relative path means something different depending on where a script is launched from.
Cybersecurity angle: Repeated cd .. (../../../etc/passwd) is the exact mechanism behind directory/path traversal attacks against web apps that build file paths from user input.
File Types (first character of ls -l output)

The first character of a long listing tells you what kind of file you're looking at.

d directory · - regular file · l symbolic link (points to another file) · s socket (free two-way process communication) · p pipe (one-way process communication) · b block file (fixed-size hardware I/O) · c character file (one-character-at-a-time hardware I/O).

Sysadmin angle: Recognizing device files (b/c) versus regular files prevents accidentally cat-ing a block device and hanging a terminal.
Cybersecurity angle: A regular file appearing where a symlink is expected (or vice versa) is a classic symlink-attack / TOCTOU red flag worth investigating.

Permissions & Ownership

Permission Bits (rwx / Owner-Group-Other)

drwxrwxrwx breaks into three sets of three: owner, group, others — each set is read (r), write (w), execute (x).

Full ls -l line, left to right: permissions → hard link count → owner user → group owner → file size (bytes/KB) → timestamp → filename.

Sysadmin angle: Reading a permission string correctly is the single most-used diagnostic skill for "why can't this service write its own log file" tickets.
Cybersecurity angle: World-writable files (write permission set in the "others" column) are one of the most common misconfiguration findings in a security audit — they let any local user tamper with data or binaries.
su / sudo — Switch User / Super User Do

su temporarily becomes another user (commonly root) inside a new shell — exit leaves it. sudo runs a single command as super user without opening a new shell.

Key flag: sudo -u [username] [command] — run as a specific user, not just root.

Sysadmin angle: sudo is the standard hardening practice over su — it's logged per-command, whereas a full su session hides exactly what was run inside it.
Cybersecurity angle: Every sudo invocation is auditable in /var/log/auth.log — exactly the kind of entry a SIEM watches for unusual privilege escalation.
chmod — Change Mode

Changes who can read/write/execute a file. Only root or the file's owner can do it.

chmod [(SET)(ACTION)(PERMISSIONS)] FILE

SET: u/g/o/a (user/group/other/all) · ACTION: +/=/- (add/set/remove) · PERMISSIONS: r/w/x.

Sysadmin angle: Correct chmod use keeps a web server able to read its own files without being writable by every user on the box.
Cybersecurity angle: Overly permissive chmod 777 is one of the most common findings on security hardening checklists — it directly violates the principle of least privilege.
Execute a File

Run a script or program sitting in the current directory with ./filename.

Example: ./hello.sh

Sysadmin angle: The ./ prefix is required because, unlike Windows, Linux doesn't search the current directory by default — a deliberate design choice.
Cybersecurity angle: That same design choice is why PATH-hijacking (tricking a victim into running ./malicious disguised as a common command) is a known local privilege-escalation technique — always verify what you're about to execute.
chown — Change Owner

Changes who owns a file or directory.

chown [OPTIONS] [NEW OWNER] FILE

Sysadmin angle: Used constantly after moving files between users' home directories or restoring backups, so the new owner can actually access their own data.
Cybersecurity angle: Auditors specifically check for root-owned files writable by non-root users, and for services running as a user that owns files it shouldn't — both are privilege-escalation paths.

Viewing & Searching

cat — Concatenate & Display Files

Dumps a file's entire contents to the screen.

cat [OPTIONS] [FILE]

Sysadmin angle: The fastest way to quickly check a small config file's contents without opening an editor.
Cybersecurity angle: cat /var/log/auth.log was the literal first step in my Lab 4.1 (Log Analysis) SEC+ lab — reading raw authentication logs by hand before hunting anomalies.
head — Show Beginning of a File

Shows the first however-many lines of a file.

head [OPTIONS] [FILE]

Example: head -5 alpha.txt

Sysadmin angle: Perfect for peeking at the top of a huge log file (headers, timestamps, format) without loading the whole thing.
Cybersecurity angle: sudo cat /var/log/auth.log | head -50 was used directly in Lab 4.1 to learn the normal shape of an auth-log entry before spotting attack traffic.
tail — Show End of a File

Shows the last however-many lines of a file.

tail [OPTIONS] [FILE]

Example: tail -5 alpha.txt

Sysadmin angle: tail -f (follow) is the everyday way to watch a log file update live while troubleshooting a running service.
Cybersecurity angle: Watching the tail of an auth or web-server log in real time is a lightweight, no-tooling way to catch an active brute-force or scan as it happens.
grep — Global Regular Expression Print

Searches text for a pattern and prints matching lines.

grep [OPTIONS] PATTERN [FILE]

Example: grep sysadmin passwd — find "sysadmin" inside the passwd file.

Sysadmin angle: The default tool for filtering noisy logs and config files down to only the lines that matter.
Cybersecurity angle: sudo grep "Failed password" /var/log/auth.log was used directly in Lab 4.1 to isolate brute-force attempts — the hand-run version of the exact query logic a SIEM like Wazuh automates.
Regular Expressions — Basic (BRE) vs Extended (ERE)

Patterns that describe text to match, rather than literal text.

Basic: . any one character · [ ] any one listed character · [^ ] NOT the listed character · * zero or more of the previous character · ^ start of line · $ end of line.

Extended (-E / egrep): + one or more · ? optional · { } min/max count · | logical OR · ( ) groups.

Sysadmin angle: A well-built regex turns a 10,000-line log into the five lines you actually need to read.
Cybersecurity angle: Regex is the language SIEM detection rules and IDS signatures are written in — learning grep regex by hand is directly learning how tools like Wazuh or Snort express what "suspicious" looks like.

File Operations

cp — Copy Files and Directories

Copies a file to a new location.

cp [OPTIONS] (SOURCE) (DESTINATION)

Example: cp /etc/passwd . — . is shorthand for "current directory."

Sysadmin angle: Always the first step before editing a critical config file — copy it somewhere safe before touching the original.
Cybersecurity angle: Attackers use cp to stage copies of sensitive files (like /etc/shadow) into world-readable locations before exfiltrating them — unexpected copies of credential files are a strong indicator of compromise.
dd — Data Duplicator (low-level copy)

Copies raw data block-by-block, bypassing the filesystem-level logic cp relies on.

dd if=[input file] of=[output file] bs=[block size] count=[# blocks]

Example: dd if=/dev/zero of=/tmp/swapex bs=1M count=50

Note: if cp can't handle a file, use dd — otherwise use cp.

Sysadmin angle: The standard tool for imaging entire disks or creating bootable USB drives, since it copies at the byte level, not the file level.
Cybersecurity angle: dd is how forensic investigators create bit-for-bit disk images for evidence — and, in the wrong hands, how someone silently wipes a disk (dd if=/dev/zero of=/dev/sda) without normal file-deletion traces.
mv — Move / Rename Files and Directories

Moves a file to a new location, or renames it in place.

mv [SOURCE file(s)] [DESTINATION]

Example: mv numbers.txt alpha.txt letters.txt School

Sysadmin angle: Renaming a service's config file to .bak before replacing it is a quick, reversible safety net during changes.
Cybersecurity angle: Malware commonly mvs itself into a legitimate-looking system path and renames itself after a common process — file-name masquerading is a standard evasion technique worth checking for.
rm — Remove Files and Directories

Deletes files or directories.

rm [OPTIONS] FILE

Key flags: -r / -R recursive — deletes everything inside a directory, including itself.

Sysadmin angle: The most dangerous everyday command — always pwd and double-check the target before running rm -r, since there's no recycle bin.
Cybersecurity angle: Attackers use rm (or disk-wipe tools built on the same idea) to delete logs and cover their tracks after an intrusion — missing expected log entries is itself an indicator worth flagging.

System & Network

shutdown

Safely brings the system down.

shutdown [OPTIONS] TIME [MESSAGE]

Example: shutdown now "Goodbye World!"

Sysadmin angle: Always prefer shutdown over pulling power — it lets running services close out and the filesystem unmount cleanly, avoiding corruption.
Cybersecurity angle: An unscheduled shutdown or reboot on a production server outside a maintenance window is a notable event worth alerting on — it can indicate a compromised admin account or an attacker covering tracks.
ifconfig / ping

ifconfig (Interface Configuration) displays network configuration info (IP, MAC, status). ping tests reachability to another host.

ifconfig [OPTIONS]

Example: ping -c 4 192.168.1.2 — ping 4 times, then stop.

Sysadmin angle: ifconfig is the first command run when troubleshooting "why can't this machine reach the network."
Cybersecurity angle: This is essentially the command I used in Lab 2.1 (Network Segmentation) — ip addr show is the modern equivalent — paired with ping to prove which network segment a host can and can't reach.
ps — Processes

Lists currently running processes.

ps [OPTIONS]

Output columns: PID unique process ID · TTY terminal name · TIME CPU time used · CMD command that started it. Flags: -e every process · -f full detail · -ef both.

Sysadmin angle: The go-to command to find and confirm the PID of a hung or misbehaving service before killing it.
Cybersecurity angle: ps -ef is a core live-response technique for spotting a malicious or unexpected process — an unfamiliar CMD entry running from /tmp is a classic sign of compromise.

Package & User Management

dpkg / apt-get

dpkg (Debian Package) is the low-level package manager; apt-get is the friendlier front-end for it.

Examples: sudo apt-get update (refresh package lists, doesn't upgrade) · apt-cache search [keyword] · sudo apt-get install [package] · apt-get upgrade [package] · apt-get remove [package] (uninstall, keep config files) · apt-get purge [package] (uninstall completely).

Sysadmin angle: Keeping systems patched via apt-get update && apt-get upgrade is one of the single highest-value routine maintenance tasks.
Cybersecurity angle: Unpatched software is a top root cause in breach reports — package management discipline is a direct, practical defense against known-vulnerability exploitation.
passwd

Updates or checks a user's password.

passwd [OPTIONS] [USER]

Example: passwd -S sysadmin shows status: username, status, last change date, min/max days, warning threshold, inactive threshold.

Status codes: P usable password · L locked · NP no password.

Sysadmin angle: passwd -S is a quick way to confirm an account isn't accidentally left with no password, or locked when it shouldn't be.
Cybersecurity angle: The min/max/warn/inactive fields passwd -S reveals map directly to SEC+ account-management controls — enforcing password expiration and lockout thresholds is a named exam topic.
I/O Redirection (> / >>)

> sends a command's output into a file, overwriting it. >> appends to the end of a file instead.

Example: echo "..." > sdfuiob.txt vs. echo "..." >> sdfuiob.txt

Sysadmin angle: Redirecting command output into log or report files is the backbone of shell scripting and automated reporting.
Cybersecurity angle: Knowing > vs >> matters operationally — accidentally using > on a log file truncates and destroys prior evidence instead of preserving it.
