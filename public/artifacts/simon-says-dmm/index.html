How it maps to the Multisim schematic

Switches → sketch keys

S1–S4 (D2–D5) are keys 1–4 in the Serial Monitor and S5 (D10) is 5. a turns all four LEDs on, 0 turns everything off.

Buttons → press them

S6–S9 are the four real buttons. The 35 kΩ pull-ups R10–R13 are inside the chip, so there is nothing to probe there.

Ground links

R5–R9 and R14–R17 are the 10 Ω links from row a to the − rail. Every − rail hole is the same ground node.

XMM1 → your handheld DMM

Mini grabbers hook onto a short jumper pushed into each test hole, so your hands stay free. For current, the red grabber hooks a lifted resistor leg so the meter sits in series.

Before you measure

  1. Upload the test sketch below. It replaces the game for now, so you can hold one pin HIGH at a time the way the Multisim switches do.
  2. Open Tools › Serial Monitor at 9600 baud. Type a key and press Enter to set the board state each row asks for.
  3. Every hole a row names is a test point. Push one end of a spare jumper into that hole and hook the grabber on the jumper's other end. The 3D view shows these as short white jumpers.
  4. Set the dial and move the red lead before the grabbers go on the circuit. Move the red lead back to VΩ after every current reading, or the next voltage reading shorts the meter and blows its fuse.
  5. Re-upload the Simon Says game when you are done.
// Simon Says measurement test sketch (stands in for Multisim S1-S5)
const byte OUT[] = {2, 3, 4, 5, 10};   // D2-D5 LEDs, D10 buzzer

void setup() {
  for (byte i = 0; i < 5; i++) pinMode(OUT[i], OUTPUT);
  for (byte p = 6; p <= 9; p++) pinMode(p, INPUT_PULLUP);   // same as the game
  Serial.begin(9600);
  Serial.println("1-4 = one LED, 5 = buzzer, a = all LEDs, 0 = all off");
}

void loop() {
  if (!Serial.available()) return;
  char c = Serial.read();
  if (c != 'a' && (c < '0' || c > '5')) return;   // ignore Enter
  for (byte i = 0; i < 5; i++) digitalWrite(OUT[i], LOW);
  if (c == 'a') for (byte i = 0; i < 4; i++) digitalWrite(OUT[i], HIGH);
  else if (c != '0') digitalWrite(OUT[c - '1'], HIGH);
}

Measurements (same IDs as Multisim)

Click any measurement to set up the meter on the 3D bench: dial, red-lead jack, and where each grabber hooks on. The meter shows the Part I hand-calculated value. Your reading is close enough if it lands in the green range under it.

Readings too low, or jumping around? The pin probably isn't held HIGH. The Simon Says game sketch only turns each LED on for short bursts (150 ms out of every 600 ms while it waits to start), and a DMM shows the average, so you get numbers between the real value and zero. Example from our board: I_Red read 3.3 mA instead of about 13 mA, which is 25% of the real current because red was on 25% of the time, and V_pin read 2.5 V instead of about 5 V. Those readings are real, but they are averages, so don't put them in the report. Fix: upload the test sketch above and type the key (red = 1), so the LED stays on steady. With the game sketch you can also press and hold a color's button during a round; that LED stays on while you hold it. I_total and the buzzer still need the test sketch.
Buzzer readings (M28–M31): before typing 5, check the buzzer's + leg (marked + on top, longer leg) is in f28 and the other leg in e28, the orange jumper runs D10 to j28, and the 10 Ω link runs a28 to the − rail. The real buzzer has no settings to change: its 5 V, 30 mA rating and about 2300 Hz tone are built in, which is what the Multisim LS1 settings copy. Holding D10 HIGH draws about 28 mA, over the pin's 20 mA recommended level (report Part I, Section 6), so type 0 as soon as each reading settles. The buzzer's own oscillator makes the meter flicker slightly; read the steady middle value.
Measuring resistance: an ohmmeter has to measure a part with no power on it and nothing else connected. Use your spare 220 Ω and 10 Ω off the board. Measured in place, the other parts and the 5 V supply add their own paths and the reading comes out wrong.

Comparing to Multisim

Real pins sag a little

Multisim's V1 is a perfect 5 V. An UNO pin drops to about 4.7–4.9 V under 10–15 mA, so the 220 Ω voltage and the currents read up to about 15% under the hand calc. That is why most ranges stop at the expected value.

The pull-up is inside the chip

Multisim uses 35 kΩ. The real ATmega328P pull-up is anywhere from 20 to 50 kΩ, so the pressed-button readings (M25, M26) have wide ranges.

Buzzers vary by model

Multisim models the buzzer as 5 V at 30 mA. Real active buzzers draw roughly 15–30 mA, so M29–M31 can sit well under the estimate and still be right.
