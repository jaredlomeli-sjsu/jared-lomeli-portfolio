Module 0 — Orientation: What Cybersecurity Actually Is

The shape of the field

  • Cybersecurity is not one job. It is a constellation of disciplines.
  • Offensive work: red team, penetration testing, exploit development.
  • Defensive work: blue team, SOC analysis, incident response, forensics.
  • Governance work: risk, compliance, audit, policy.
  • Engineering work: AppSec, cloud security, identity, platform security.

Foundational concepts

  • CIA Triad: Confidentiality, Integrity, Availability.
  • AAA Model: Authentication, Authorization, Accounting.
  • Risk = Threat × Vulnerability × Impact.
  • Every control you ever deploy supports one of these properties.


The CIA Triad — the conceptual bedrock of every security control.

Real-world application: A hospital ransomware attack hits all three legs of the triad — patient records become unreadable (confidentiality and integrity threatened), and life-critical systems go offline (availability lost).

You should be able to explain: why availability is a security concern (not just reliability); why "the attacker only needs to be right once" is misleading; the difference between a vulnerability and a misconfiguration.

Module 1 — Electronics Foundations

Why electronics matters for security

  • At the lowest layer, cybersecurity is electricity.
  • Hardware implants, side-channel attacks, and IoT bugs all live here.
  • Physics-level attacks (Rowhammer, Spectre, voltage glitching) require this base.

The language of circuits

  • Voltage — potential difference (volts).
  • Current — flow of charge (amps).
  • Resistance — opposition to current (ohms).
  • Ohm's Law — V = I × R. Memorize this one equation.
  • DC vs AC — DC powers logic; AC arrives at the wall.

Core components

  • Resistors limit current.
  • Capacitors store charge and smooth signals.
  • Inductors resist change in current.
  • Diodes enforce one-way flow.
  • Transistors amplify and switch — the keystone of all digital logic.

From transistors to computers

  • Logic gates (AND, OR, NOT, NAND, XOR) are built from transistors.
  • Gates compose into adders, multiplexers, flip-flops.
  • Flip-flops compose into registers and memory.
  • Memory + ALU + control unit = a CPU.
  • A microcontroller is a tiny CPU on one chip — used in cars, bulbs, sensors.


Ohm's Law — V = I × R.


Arduino Uno — a beginner microcontroller for hands-on learning.

Real-world application: The Stuxnet worm (2010) crossed from software into the physical world — manipulating Siemens PLC firmware to spin Iranian centrifuges to destruction. Without electronics literacy, you cannot read that story.

Quick stats:

  • ~30 billion IoT devices online by 2025 (IoT Analytics).

You should be able to explain: what a transistor does in plain language; why digital logic is built from NAND gates so often; why every "smart" device is a security concern by default.

Module 2 — How Computers Work

Why this matters

  • Buffer overflows live in the gap between what programmers think computers do and what they actually do.
  • Privilege escalation, race conditions, rootkits — all rooted here.

Representation

  • Binary is the substrate.
  • Hexadecimal is the human-readable shorthand.
  • Two's complement is how negative numbers are encoded.
  • ASCII and Unicode encode text into bytes.

Architecture (von Neumann)

  • CPU connected to memory and I/O over buses.
  • Fetch–decode–execute cycle drives every instruction.
  • Code and data share memory — which is why data can become code.
  • Memory hierarchy: registers → cache → RAM → disk (each slower, larger).
+---------------------------------+
|              CPU                |
|   ALU --- Registers --- Control |
+---------------------------------+
              |
         System Bus
              |
       +------+------+
       |             |
      RAM           I/O

The operating system

  • Schedules processes — gives each one CPU time.
  • Provides virtual memory — illusion that each process owns the machine.
  • Mediates hardware access through system calls.
  • Enforces user mode vs. kernel mode boundary.
  • Almost every privilege escalation is that boundary failing.

The boot chain

  • Firmware (BIOS / UEFI) → Bootloader → Kernel → Init system.
  • Earliest code wins — so rootkits and bootkits hide there.

Real-world application: The Spectre and Meltdown vulnerabilities (2018) exploited speculative execution in CPUs — a hardware-level optimization — to leak memory across security boundaries. Affected nearly every CPU made in 20 years.

You should be able to explain: the difference between a process and a thread; why virtual memory exists; what happens when a program calls open(); why "ring 0" is the phrase attackers care about.

Module 3 — The Unix Worldview

Why Unix

  • Linux powers most of the internet.
  • Almost every security tool is built on it.
  • The Unix philosophy — small composable programs — shapes how security work is done.

Core concepts

  • The file system is a tree — devices and processes are also files.
  • Permissions: read, write, execute × user, group, other.
  • Special bits: SUID, SGID, sticky — source of countless privilege escalations.
  • Every process has: a parent, an environment, file descriptors, a UID.
  • The shell is a programming language, not just a prompt.

Tools to know cold

  • grep, awk, sed — text processing.
  • find, xargs — locating and acting on files.
  • cut, sort, uniq, tr — column-level data wrangling.
  • ps, top, htop — process inspection.
  • ssh, scp, rsync — remote access and transfer.

Real-world application: The 2021 Log4Shell vulnerability was triaged across the world from the Linux command line. Defenders used grep, find, and curl to identify vulnerable servers — basic Unix fluency was the difference between hours and weeks of response time.

You should be able to explain: what chmod 4755 does and why an attacker would care; why sudo is more nuanced than "run as root"; what a pipe does at the kernel level.

Module 4 — Networking from the Wire Up

The layered mental model

  • Most attacks traverse a network — you must be able to reason about it.
  • The OSI model has 7 layers; the TCP/IP model collapses it to 4.
  • Each layer hides the layer below and exposes a service to the layer above.


The OSI seven-layer model — every networking concept maps here.

Layer 2 — Ethernet & Switching

  • MAC addresses identify network interfaces.
  • Switches forward frames using a learned MAC-to-port map.
  • ARP bridges link layer to network layer (IP → MAC).
  • ARP is unauthenticated → ARP spoofing is the first attack to learn.

Layer 3 — IP & Routing

  • IPv4 = 32 bits; IPv6 = 128 bits.
  • Subnetting partitions an address space using a mask.
  • CIDR notation: /24 = 256 addresses, /16 = 65,536.
  • RFC 1918 reserves private ranges (10.x, 172.16.x, 192.168.x).
  • NAT lets many private addresses share one public one.

Layer 4 — TCP & UDP

  • TCP — connection-oriented, reliable byte stream.
  • 3-way handshake: SYN → SYN-ACK → ACK.
  • UDP — connectionless, fast, easier to spoof and abuse for amplification.
   Client                              Server
     |---------- SYN (seq=x) ---------->|
     |<------ SYN-ACK (ack=x+1) --------|
     |---------- ACK (ack=y+1) -------->|
     |       Connection established     |

Layer 7 — Application protocols

  • HTTP / HTTPS — web request-response.
  • DNS — names → addresses (cache poisoning, hijacking, tunneling).
  • SMTP / IMAP / POP3 — email plumbing.
  • SSH — authenticated remote shells.
  • DHCP — hands out IPs to joining clients.

Practical analysis tools

  • Wireshark / tcpdump — capture and decode traffic.
  • Nmap — discover hosts and probe ports.
  • scapy — craft custom packets in Python.

Real-world application: The Mirai botnet (2016) scanned the internet for IoT devices using default credentials on port 23 (Telnet) and port 2323. At its peak it took down DNS provider Dyn — knocking Twitter, Netflix, and Reddit offline. Defense started with watching the right ports.

You should be able to explain: what happens, end-to-end, when you type a URL into a browser; why a SYN flood works; the difference between a switch, a router, and a firewall.

Module 5 — Threats and Adversaries

Who attacks, and why

  • Script kiddies — run other people's tools; low skill, high noise.
  • Criminal groups — optimize for revenue (ransomware, BEC, fraud).
  • Hacktivists — pursue political goals.
  • Insiders — abuse legitimate access.
  • Nation-states — long timelines, deep budgets, custom tooling.

Frameworks worth internalizing

  • MITRE ATT&CK — matrix of real-world tactics and techniques.
  • Cyber Kill Chain — Recon → Weaponize → Deliver → Exploit → Install → C2 → Actions.
  • STRIDE — Spoofing, Tampering, Repudiation, Info disclosure, DoS, Elevation.

Major attack categories

  • Social engineering — phishing, vishing, pretexting.
  • Malware — viruses, worms, trojans, ransomware, rootkits, info-stealers.
  • Denial of service — volumetric, protocol, application-layer.
  • On-path (MITM) — intercepting and modifying traffic.
  • Password attacks — brute force, credential stuffing, dictionary.
  • Injection — SQL, command, template — data interpreted as code.

Module 6 — Cryptography as a User

The primitives

  • Symmetric encryption — one shared key. Standard: AES.
  • Asymmetric encryption — keypair. RSA, ECC.
  • Hashing — one-way fingerprint. SHA-256, SHA-3.
  • HMAC — hashing with a secret key, for authentication.
  • Digital signatures — combine asymmetric crypto and hashing.

Modes matter

  • ECB mode leaks structure — never use it.
  • CBC mode is OK with proper IVs and padding.
  • GCM mode is the modern default — encryption + integrity.


Original — ECB mode (structure leaks) — secure mode (looks like noise).

Public Key Infrastructure (PKI)

  • Certificate Authorities sign certificates.
  • Browsers ship with a list of trusted root CAs.
  • TLS uses certificates to authenticate servers.
  • The chain of trust is what stops impersonation of bank.com.

Password storage

  • Plain hashing is not enough — rainbow tables defeat it.
  • Use a salt — unique per user.
  • Use a slow function — bcrypt, scrypt, or Argon2.

Real-world application: The 2012 LinkedIn breach exposed 117 million passwords stored as unsalted SHA-1 hashes. Within days, more than 90% were cracked. The same data still appears in credential-stuffing attacks today.

You should be able to explain: why ECB is broken with a single picture; why hashing alone is insufficient for password storage; what a Certificate Authority is actually attesting to.

Module 7 — Defending Systems and Networks

Defense in depth

  • No single mechanism is sufficient.
  • Assume any one layer will eventually fail.
  • Ask: what catches the attacker next?

Firewalls

  • Packet filter — looks at each packet in isolation.
  • Stateful — tracks connections, allows reply traffic.
  • Application-layer — understands HTTP, DNS, etc.
  • On Linux: iptables / nftables.

IDS / IPS

  • Signature-based — matches known-bad patterns.
  • Anomaly-based — flags unusual behavior.
  • Open-source standards: Snort, Suricata, Zeek.

Endpoint protection

  • Classic AV — signature matching.
  • EDR — records process, network, file behavior; chains events.
  • XDR — extends across endpoint, network, cloud, identity.

SIEM and logging

  • Centralize logs from across the environment.
  • Correlate events into alerts.
  • Common stacks: Wazuh, Elastic, Splunk.

Hardening and hygiene

  • Disable services you do not use.
  • Patch promptly — most exploits target known CVEs.
  • Follow CIS benchmarks.
  • 3-2-1 backup rule: 3 copies, 2 media, 1 off-site.

Identity is the new perimeter

  • Multi-factor authentication — phishing-resistant where possible.
  • Least privilege.
  • Zero trust — authenticate every request, trust no network.

Real-world application: Google's BeyondCorp project replaced VPN-based perimeter security with a zero-trust model after the 2009 Aurora attacks. Today, no Google employee is trusted by network location — only by identity, device posture, and request context.

You should be able to explain: why "we have a firewall" is not an answer to anything; what an EDR sees that an antivirus does not; the failure mode of an alerting system nobody reads.

Module 8 — Web Application Security

How the web works (in 30 seconds)

  • HTTP is stateless — request goes out, response comes back.
  • Cookies and sessions fake state on top of it.
  • Browsers enforce the same-origin policy.
  • CORS opens controlled holes in that policy.

OWASP Top 10 (2021)

  • A01 — Broken Access Control.
  • A02 — Cryptographic Failures.
  • A03 — Injection (SQL, command, LDAP).
  • A04 — Insecure Design.
  • A05 — Security Misconfiguration.
  • A06 — Vulnerable & Outdated Components.
  • A07 — Identification & Auth Failures.
  • A08 — Software & Data Integrity Failures.
  • A09 — Logging & Monitoring Failures.
  • A10 — Server-Side Request Forgery (SSRF).

Attacks worth deep study

  • SQL injection — input becomes query syntax.
  • XSS — input becomes script in someone else's browser.
  • CSRF — victim's browser is tricked into sending an authenticated request.
  • SSRF — server is tricked into making requests to internal targets.
  • IDOR — change a URL ID, get someone else's data.

Real-world application: The 2017 Equifax breach — 147 million records exposed — began with a single unpatched Apache Struts CVE on a public web app. Categorically: A06 (vulnerable components). One missed patch, $1.4 billion in penalties.

You should be able to explain: why the same-origin policy exists; what makes XSS different from SQLi in terms of who gets attacked; why prepared statements are not optional.

Module 9 — The Offensive Mindset

The pentest methodology

  • Reconnaissance — gather public info, no contact.
  • Scanning — probe for hosts and services.
  • Enumeration — extract detail (versions, users, shares).
  • Exploitation — turn vulnerability into access.
  • Post-exploitation — persist, escalate, pivot.
  • Reporting — where the actual value gets delivered.

Beginner-friendly platforms

  • TryHackMe — guided rooms, gentle ramp.
  • HackTheBox — unguided machines, harder.
  • PortSwigger Web Academy — best free web-exploit training.
  • PicoCTF — gamified intro for younger learners.
  • OverTheWire — Linux & networking wargames.

The legal and ethical frame

  • Test only systems you own or have explicit written permission for.
  • The Computer Fraud and Abuse Act (US) treats unauthorized access as a serious crime.
  • The line between "researcher" and "criminal" is paperwork.


Kali Linux — the standard distribution for offensive work.

Real-world application: Bug bounty programs from Google, Microsoft, and Apple paid out over $250 million combined since inception. Researchers using only the platforms above have built six-figure incomes — the offensive mindset has a market.

You should be able to explain: the difference between a vulnerability scanner and a penetration test; why reporting is the hardest part; what "scope" means in an engagement.

Module 10 — Specialization Paths

Where to go next

  • Blue team — SOC, IR, threat hunting, forensics.
  • Red team — pentest, exploit dev, adversary emulation.
  • AppSec — code review, threat modeling, SAST/DAST.
  • Cloud security — AWS, Azure, GCP — each its own world.
  • GRC — governance, risk, audit, compliance.
  • OT / ICS security — industrial control, critical infrastructure.

First certifications worth pursuing

  • Foundation: CompTIA Security+.
  • Offensive: eJPT, then PNPT or OSCP.
  • Defensive: BTL1, CySA+, GCIH.
  • Cloud: AWS Security Specialty, CCSP.
  • Senior: CISSP (after 5 years experience).
