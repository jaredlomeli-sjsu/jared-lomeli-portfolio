Security & Privacy

How this site is protected, what it stores, what I checked before publishing, and where the limits are. Last reviewed October 2026.

What this site is

A static site: HTML, CSS, JavaScript and PDFs served from Vercel. There is no database, no login, no form that sends data to me, no analytics and no advertising. It sets no cookies. The only thing it stores in your browser is your light/dark preference (localStorage key theme), which never leaves your device.

Two things can contact a third party, and only if you use them: opening a project video loads a YouTube player from youtube-nocookie.com, and a few demo pages under /demo/ load fonts, images or a chart/3D library from Google Fonts, Wikimedia, jsDelivr or unpkg.

Protections in place

  • Content Security Policy. The main pages allow scripts and styles only from this site: no inline scripts, no inline event handlers, no inline styles. Framing is limited to this site (and the YouTube privacy-enhanced player), plugins are blocked, and the base URL and form targets are locked.
  • Transport. HTTPS only, with HSTS (two years, including subdomains, preload) and upgrade-insecure-requests.
  • Browser hardening headers. X-Content-Type-Options: nosniff, X-Frame-Options: SAMEORIGIN, Referrer-Policy: strict-origin-when-cross-origin, a restrictive Permissions-Policy (camera, microphone, location, payment, USB, serial and Bluetooth off), and Cross-Origin-Opener-Policy / Cross-Origin-Resource-Policy: same-origin.
  • Output escaping. Text from the content file is escaped before it is placed into the page, including inside quoted attributes; most fields are written with textContent.
  • Safe external links. Links that open a new tab use rel="noopener".
  • Pinned third-party code. Demo pages that load libraries from a CDN pin an exact version and verify it with Subresource Integrity hashes.
  • Nothing extra published. Source notes, tests, scripts and config are excluded from the deployed site, and the repository contains no secrets or credentials.
  • Disclosure contact. /.well-known/security.txt.

Privacy review of published content

Before publishing coursework I check every PDF, image and page for personal information, and re-ran a full audit in October 2026 (text, metadata, image EXIF/GPS, unlinked files, git history).

Check Result
Student ID, date of birth, SSN-style numbers Redacted in the unofficial transcript; none found elsewhere.
Other people's names Classmate names removed from peer-review documents; lab partners are not named.
Personal reflection content One assignment of a personal nature was taken down.
Image metadata (EXIF, GPS, device) None present in any published image.
Secrets, API keys, tokens, private paths None in the site or its git history. Lab documents use private-range or textbook example addresses only.
Contact details My résumé and cover letters include my phone number and city (no street address). That is deliberate, for employers.

Known limits

  • Document pages under /public/ and the demo pages use style-src 'unsafe-inline', and the demos and one lab write-up also use inline scripts. They are isolated from the main pages by a separate policy but are not as strict. One demo (the Linux security infographic) is an exported bundle that also needs blob: URLs and React from unpkg, so its policy is the loosest on the site.
  • There is no Trusted Types policy; adding a pass-through one would look like protection without providing any.
  • Static files are served with Vercel's default Access-Control-Allow-Origin: *. Everything on the site is public by design.
  • The site's source is also in a public GitHub repository, so removed or redacted files may still exist in its earlier history.
  • Hosting security (TLS, DDoS protection, platform patching) is Vercel's responsibility, not mine.
  • This is a personal student site, not a hardened production service. I have not had it independently penetration-tested.
